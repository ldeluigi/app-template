# Web distribution, store policy/IP risk and input licences for agent-built 2D physics games (Kotlin Multiplatform + Compose), as of 2026-11-13

Scope notes. Not legal advice. Sources dated before 2025 are marked **[stale?]**. Earnings from guides or developers are marked **[self-reported/secondary]**. "Measured 2026-11-13" means I fetched the file myself in this session. Facts I could only recall but not source are in *Gaps*, not in *Cited Findings*.

## 1. Web distribution: can a Kotlin/Compose 2D game reach browser portals, and what is it worth?

### Takeaway
Yes, technically: Compose Multiplatform for web (Kotlin/Wasm, Skia canvas) is **Beta** (since 1.9.0, Sept 2025; still Beta at 1.12.x, Oct 2026), runs in Chrome/Edge 119+, Firefox 120+ and Safari/iOS 18.2+, has an official Kotlin/JS fallback build, and a current demo downloads about **4.3 MB gzip (12.4 MB raw)** before any game content, which fits CrazyGames (50 MB, 20 MB for the mobile homepage) and YouTube Playables (30 MiB) but is at the edge of Poki's "under 5 MB initial / 8 MB total" guidance. Commercially the web is a lottery ticket, not a plan: portals are curated, Poki wants 5-year web exclusivity, published medians are near zero, and the only hard physics-game number found is the outlier Drive Mad (over $1M in 12 months on Poki).

### Cited Findings

#### Compose Multiplatform for web: status, browsers, size
- Stability table: "Web based on Kotlin/Wasm: Beta" for both Kotlin Multiplatform core and the Compose Multiplatform UI framework; Kotlin/JS is Stable for KMP core but is not listed as a Compose UI target — [Kotlin docs, supported platforms](https://kotlinlang.org/docs/multiplatform/supported-platforms.html)
- Web went Beta in Compose Multiplatform 1.9.0 (Sept 2025). JetBrains' roadmap to Stable lists: drag-and-drop in mobile browsers, better accessibility, and "addressing issues related to the `TextField` component" — [What's new in CMP 1.9.0](https://kotlinlang.org/docs/multiplatform/whats-new-compose-190.html), [JetBrains blog](https://blog.jetbrains.com/kotlin/2025/09/compose-multiplatform-1-9-0-compose-for-web-beta/)
- Kotlin/JS fallback exists: the `composeCompatibilityBrowserDistribution` Gradle task "combines Kotlin/JS and Kotlin/Wasm distributions into a single package. This allows Wasm applications to fall back to the JS target when modern Wasm features are not supported by a browser" — [What's new in CMP 1.9.0](https://kotlinlang.org/docs/multiplatform/whats-new-compose-190.html)
- Accessibility on web is "initial": screen readers get description labels and can click buttons; not supported: interop/container views with scrolls and sliders, traversal indexes. `WebElementView()` overlays HTML elements on the canvas — [What's new in CMP 1.9.0](https://kotlinlang.org/docs/multiplatform/whats-new-compose-190.html)
- Compose Multiplatform 1.12.0 was released 2026-08-26; its only web item is automatic font fallback: on an uncovered character the web target "downloads the matching Noto font subset on demand and recomposes the affected text" (tofu may show briefly). The docs page is headed 1.12.2 and dated 15 Oct 2026 — [JetBrains blog 1.12.0](https://blog.jetbrains.com/kotlin/2026/08/compose-multiplatform-1-12-0/), [What's new in CMP 1.12](https://kotlinlang.org/docs/multiplatform/whats-new-compose-112.html)
- Newest published artifacts (measured 2026-11-13): `org.jetbrains.compose.ui:ui` release = 1.13.0-beta02; `org.jetbrains.skiko:skiko` = 0.156.1; both Apache-2.0 in their POMs — [Maven Central, compose ui](https://repo1.maven.org/maven2/org/jetbrains/compose/ui/ui/maven-metadata.xml), [Maven Central, skiko](https://repo1.maven.org/maven2/org/jetbrains/skiko/skiko/maven-metadata.xml)
- Browser floor for Kotlin/Wasm (WasmGC + exception handling): Chrome and Chromium-based (Edge, Brave, Opera, Samsung Internet) 119+, Firefox 120+, Safari/WebKit 18.2+ (iOS/iPadOS 18.2, macOS 15.2, also Sonoma/Ventura); older Safari "not supported". Page dated 22 May 2026 — [Kotlin docs, Wasm configuration](https://kotlinlang.org/docs/wasm-configuration.html)
- Size, measured 2026-11-13 on a public Compose/Wasm "Jetsnack" demo (files last modified 2026-10-07; the server offers gzip only, no brotli): larger `.wasm` (Skiko-sized) 8,405,289 bytes raw / 3,266,573 gzip; app `.wasm` 3,576,781 raw / 1,004,529 gzip; JS glue 394,755 raw / 66,517 gzip. Total ≈ 12.4 MB raw, ≈ 4.34 MB gzip — [zal.im Jetsnack demo](https://zal.im/wasm/jetsnack/)
- Older community figures agree on the order of magnitude: skiko.wasm ≈ 8 MB raw, app wasm ≈ 5.7 MB unoptimised; one project reports Skiko transfer size 3.2 MB plus app 0.6–1.2 MB; a user reports brotli bringing skiko.wasm to ≈ 2.5 MB; Skiko is loaded fully before the app can start **[stale? 2023–2024, anecdotal]** — [Kotlin Slack archive](https://slack-chats.kotlinlang.org/t/16406831/question-wasmjs-compose-what-is-the-typical-size-of-wasm-fil), [compose-counting-grid README](https://github.com/OliverO2/compose-counting-grid)
- Calling a portal's JavaScript SDK from Kotlin/Wasm is supported through `external` declarations (global scope by default, or `@JsModule`), `@JsFun`/`js("…")` snippets and `@JsExport`; only a restricted set of types may cross the boundary (`JsAny` and subtypes, primitives, strings), external types cannot be implemented/extended, and JS snippets are not checked at compile time — [Kotlin docs, Wasm JS interop](https://kotlinlang.org/docs/wasm-js-interop.html)

### Inferences
- **Fit per portal for a Compose/Wasm build.** CrazyGames and Playables size limits are met with margin (≈ 4.3 MB gzip + assets vs 20/50 MB and 30 MiB). Poki's 5 MB/8 MB is guidance, not a hard cap (Godot at 10 MB and Unity at 11 MB "run on Poki"), but a Compose build starts where Poki says a finished game should end, and competes with Phaser builds 15 times smaller. Playables' "files SHOULD be under 512 KiB" is violated by an 8 MB Skiko binary (a SHOULD, not a MUST).
- **Poki's "no external requests" conflicts with Compose 1.12's on-demand Noto font download**: every glyph the game can show must be covered by bundled fonts (or the fallback disabled), otherwise text shows tofu on Poki. Needs a test.
- **iOS is the weak point.** WasmGC needs Safari 18.2 (released Dec 2024, from memory), so older iPhones need the Kotlin/JS compatibility build (slower, larger JS). CrazyGames disables games that misbehave on Safari and already disables Unity on iOS for memory; a Skia-in-Wasm runtime is in the same risk class. Must be measured on a real mid-range iPhone and Android phone before promising portal reach.
- **SDK integration is feasible but manual.** Portal SDKs are small JS APIs (init, loading finished, gameplay start/stop, commercial break, rewarded break, save data). In Kotlin/Wasm each becomes a handful of `external` functions returning `Promise`; no portal offers a Kotlin binding, and none lists Compose among supported engines, so support questions fall on the owner.
- **Template fit.** The existing seam is right: a `wasmJsMain` platform providing `Ads` (portal SDK `commercialBreak`/`rewardedBreak`, or `adBreak()` on the owner's own site), `Shop` = none (portals forbid purchase UI) and `Entitlements` = `Free`. `core` (physics, rules) is already common code and compiles to Wasm unchanged. Costs: the machinery plugins must add a `wasmJs` target, a web entry point, CI for the web build, one build flavour per portal SDK, and audio via Web Audio interop (Compose has no audio API). Licensee does not see npm/JS files such as a vendored portal SDK.
- **Kotlin/Wasm versus JS (Phaser + Matter.js/Planck.js) in a WebView.** JS serves portals better (portals' native stack, 0.3 MB runtime, works on every browser, SDK plugins exist for Phaser) but breaks the template's rules (logic in `core`, Compose for every screen, JVM tests, Licensee coverage) and repeats the 3D study's WebView-wrapper risk under Apple 4.2. Kotlin/Compose keeps one codebase and the stores as the primary product, with web as a possible second outlet. Given that web income is near zero at the median and Poki demands exclusivity only on the web, optimising the architecture for portals is not justified; keeping `core` free of platform code preserves the option at low cost.
- **Realistic route to try the web cheaply**: itch.io (no SDK, no curation, no income) as a smoke test, then CrazyGames Basic launch (no SDK needed, no ads) to see whether the game is selected for Full launch, before spending anything on Poki or Playables.
- 2D physics is a proven web genre at the top (Drive Mad), but that is one title in an exclusive, curated catalogue; it shows genre fit, not expected income.

## 2. Store policy, intellectual-property and clone risk for 2D physics genres

### Takeaway
Mechanics and rules are free in both US and EU law, but names, characters, art, music, level layouts and a game's overall "look and feel" are protected, and the famous incumbents (Tetris, Angry Birds, Suika, Cut the Rope) police stores through takedown forms that work without a court; an agent-built game must therefore be original in name, art, sound, levels and presentation and never reference an existing game. Since mid-2026 the store rules for small games changed little in substance (Apple added creative-asset rule 2.3.14 in October; Play's 12-tester rule and API 36 stand), while age-signal duties (Texas in force, Utah and Louisiana moved to 2027), Android developer verification (four countries since 30 Sept 2026, global in 2027) and the EU Digital Fairness Act proposal are the moving parts.

### Cited Findings

#### What the law protects
- US Copyright Office: "The idea for a game is not protected by copyright. The name or title given to the game and the methods for playing it are not protected by copyright"; parts with "a sufficient amount of literary or pictorial expression" (written rules, artwork) may be — [copyright.gov, Games](https://www.copyright.gov/register/tx-games.html)
- *Tetris Holding v. Xio Interactive* (D.N.J. 2012): Xio admitted copying Tetris to make "Mino" and argued it took only rules; the court held it had copied protected expression (the games' look and feel was nearly identical) and also granted summary judgment on **trade dress** infringement **[stale? but still the leading case]** — [Wikipedia summary](https://en.wikipedia.org/wiki/Tetris_Holding,_LLC_v._Xio_Interactive,_Inc.), [Loeb & Loeb](https://www.loeb.com/en/insights/publications/2012/06/tetris-holding-llc-v-xio-interactive-inc)
- *Spry Fox v. Lolapps* (W.D. Wash. 2012, Triple Town vs Yeti Town; settled): preliminary rulings held look and feel protectable; scènes à faire (coins for score) excluded, but the copied object hierarchy and expressive elements counted. *Data East v. Epyx* is cited for the opposite pole: similar ideas and principles are permissible **[stale?]** — [Wikipedia, Spry Fox](https://en.wikipedia.org/wiki/Spry_Fox,_LLC_v._Lolapps,_Inc.), [Wikipedia, Tetris v. Xio](https://en.wikipedia.org/wiki/Tetris_Holding,_LLC_v._Xio_Interactive,_Inc.)
- EU: in *Nintendo v PC Box* (C-355/12, 2014) the CJEU treated video games as complex works whose original graphic and sound elements are protected by copyright alongside the program; *SAS Institute* (C-406/10) held that a program's functionality, language and data formats are not protected expression; *Sony v Datel* (C-159/23) recently confirmed the narrow scope of program protection — [Covington on Nintendo v PC Box](https://www.insideglobaltech.com/2014/02/20/the-cjeus-nintendo-v-pc-box-proportionate-drms/), [Hogan Lovells on Sony v Datel](https://hlc.com/en/publications/is-cheating-copyright-infringement-cjeu-clarifies-specific-protection-computer-programs)
- Mechanic patents: Nintendo's Japanese suit against Palworld (monster capture/mounting patents) was narrowed to old versions, with commentators expecting at most about ¥5M; the USPTO issued a non-final rejection of all 26 claims of US 12,433,397 and the JPO rejected related applications in 2026. A Tokyo District Court opinion was scheduled for 2026-11-09; outcome not found — [GamesRadar](https://www.gamesradar.com/games/survival/as-palworld-lawsuit-drags-on-nintendo-tries-and-fails-to-secure-another-patent-on-monster-capturing-mechanics/), [Windows Central](https://www.windowscentral.com/gaming/nintendo-wanted-to-block-palworld-now-it-faces-a-0-percent-chance-and-a-measly-usd30k-payout), [Games Fray](https://gamesfray.com/category/games-intellectual-property-rights/nintendo-v-pocketpair-palworld/)

#### Enforcement by incumbents
- The Tetris Company had about 35 Tetris-style apps removed from Android Market by DMCA notice, arguing also consumer confusion **[stale? about 2010]**; in Sept 2026 it publicly warned that it takes infringement "very seriously" over a White House browser clone, which then disappeared — [Liliputing](https://liliputing.com/35-tetris-clones-removed-from-the-android-market/), [Game Developer, 2026](https://www.gamedeveloper.com/business/trump-administration-takes-down-tetris-clone-after-company-warns-it-takes-copyright-violation-very-seriously-)
- Suika Game (Aladdin X): in late 2023 look-alike apps named "Suika Game …" filled the Japanese App Store charts, some reusing the original music and near-identical art; Aladdin X warned users and reported them to Apple; a PlayStation Store knock-off appeared in Dec 2023; the official iOS app followed in 2024 — [Automaton](https://automaton-media.com/en/news/20231101-22756/), [Nintendo Wire](https://nintendowire.com/news/2023/12/21/suika-game-developer-confirms-it-is-not-involved-with-playstation-store-knock-off/), [TouchArcade](https://toucharcade.com/2024/03/27/suika-game-mobile-english-download-official-app-store-release-date-aladdin-x-iphone-ipad-android/)
- Rovio litigates on characters and marks (about $4M awarded against a toy counterfeiter) but lost oppositions against merely similar names ("Angry Bite") **[stale?]** — [PocketGamer.biz](https://www.pocketgamer.biz/rovio-wins-usd-4-million-in-copyright-dispute), [WIPR](https://www.worldipreview.com/trademark/angry-birds-lose-bite-in-trademark-claim-7078)
- Apple: guideline 4.1 — "Don't simply copy the latest popular app… or make some minor changes to another app's name or UI"; "You cannot use another developer's icon, brand, or product name in your app's icon or name". Rights holders use the App Store Content Dispute form (up to 50 apps per claim); Apple relays the claim and removes the app if the dispute is unresolved or unanswered; practitioners report about two weeks to process, cases of one to three months **[timing sources 2017–2019, stale?]** — [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/), [Apple content dispute](https://www.apple.com/legal/intellectual-property/dispute-forms/app-store), [BCF](https://www.bcf.ca/en/thought-leadership/2019/infringement-of-your-rights-by-an-app-let-apple-help-you)
- Apple also removes copycats on its own initiative months after release (developer report of a 4.1 removal, 2025) — [Apple Developer Forums](https://developer.apple.com/forums/thread/774172)
- Google Play: copyright complaints go through the legal removal form and are reported by practitioners as the fastest route; trademark complaints need a registration number; removals can be automatic on receipt of a web form, with the developer left to appeal **[secondary, partly pre-2025]** — [Sensor Tower guide](https://sensortower.com/blog/how-to-file-an-app-copyright-infringement-complaint-with-apple-and-google), [developer account, Medium](https://medium.com/%40yeoyaowei/google-screwed-our-startup-because-of-the-faceless-systems-they-use-to-deal-with-app-developers-94ca199faaca)

#### Ad placement rules for casual games
- AdMob disallows interstitials on app load or exit, after every user action ("no more than one interstitial ad after every two user actions"), back-to-back, or appearing unexpectedly "while a user is playing a game"; they belong at logical breaks "in between… stages, or levels", pre-loaded so they do not appear late; app-open ads are the format for launch — [AdMob Help](https://support.google.com/admob/answer/6201362)

### Inferences
- **Risk by genre** (from the cases above): highest where the incumbent's expression is the genre itself and the owner is litigious — falling tetrominoes on a 10×20 well (Tetris: copyright and trade dress), fruit-merge-in-a-box with a watermelon as the top item and the same fruit order (Suika: the "hierarchy of objects" logic of Spry Fox applies), slingshot with round birds and pigs in block towers (Rovio characters and marks), candy/rope/creature combination (ZeptoLab). Lower where the mechanic is generic physics and the theme is the owner's own: bridge building, stacking, pinball with an original table, peg-bouncing, marble runs, ragdoll, vehicle-over-terrain.
- **Practical rules for agents**: (1) never put another game's name, a confusingly similar name, or "‑like/clone/inspired by X" in the title, description, keywords, screenshots or code comments (Apple 4.1(c), 2.3.14; trademark); add incumbents' names to `config/forbidden-names.txt` (owner-only file) so the build fails on them; (2) original art drawn in code or CC0, never traced or recoloured from a game; (3) original level layouts and object progressions — do not reproduce an incumbent's exact set, order, sizes or colours of pieces, playfield dimensions, UI layout or scoring presentation; (4) change at least theme, object set, and one rule, so the game is not "indistinguishable" (Apple 4.3(b)) or "highly similar" (Play spam); (5) no sounds or music that imitate a known game; (6) keep a short design log of independent choices per game.
- Play's "multiple apps with highly similar content" and Apple 4.3(a) bite on the owner's own portfolio too: several physics games from one template must differ in mechanic and content, not just skin.
- Takedowns are fast and asymmetric: a rights holder's form can remove an app within days to weeks without adjudication, and on Play repeated removals threaten the account; so the risk to avoid is not losing in court but being reported at all.
- Age duties: an ad-funded game offered in Texas is formally within SB 2420; the low-effort positions are (a) do not distribute in the US, or (b) rate conservatively, serve non-personalised ads to unknown ages and add the Age Signals / Declared Age Range calls behind a `Platform` interface when the owner decides (the Play library is proprietary, so it is an owner decision under rule 3). Needs legal confirmation.
- EAA: a free game with ads only, no purchases and no chat, by a micro-enterprise, is most likely outside the Act; adding a "remove ads" purchase brings the purchase flow (largely the store's own sheet) into the discussion.
- Mechanic patents exist but are being narrowed (Palworld); for generic 2D physics the practical patent risk is low compared with copyright/trademark takedowns.

## 3. Licences for non-code inputs (art, fonts, audio, ads SDKs) under an Apache-2.0 / MIT / BSD / CC0 rule

### Takeaway
A clean policy is possible: art drawn in code or CC0 (Kenney, CC0-filtered OpenGameArt/itch.io), fonts from the Apache-2.0 directory of Google Fonts (Roboto and Open Sans are now OFL and therefore out), sound made with sfxr-family tools or ChipTone (output CC0) or taken from CC0 packs, and physics/rendering code that is already MIT/Apache; everything "free" but custom-licensed (Pixabay, Sonniss, ZapSplat, AI music) and CC-BY (Game-icons.net) is excluded. No ad network ships an allowlisted SDK: Google's ads, consent and age-signal libraries are under the Android SDK License and every alternative has its own EULA, so ads remain an owner exception, and Licensee cannot see assets at all, which calls for an asset manifest checked by a test.

### Inferences
- **Proposed asset policy.** Allowed: (1) art, particles and UI drawn in code with Compose Canvas (no licence at all, smallest download, also the best clone defence); (2) CC0 files (Kenney; OpenGameArt and itch.io packs only when the pack page itself states CC0); (3) Apache-2.0 fonts from `google/fonts/apache`; (4) sounds generated with jsfxr/sfxr/Bfxr2/ChipTone or synthesised in code, and CC0 audio (Kenney, Freesound's CC0 filter, OpenGameArt CC0). Excluded: CC-BY and CC-BY-SA (Game-icons.net, most of Freesound/OpenGameArt), OFL fonts unless the owner adds OFL-1.1 to the allowlist, Pixabay, Sonniss, ZapSplat and other custom "royalty-free" licences, AI-generated music (plan-dependent rights, litigation, thin copyright).
- OFL-1.1 is the one exclusion worth an owner decision: it permits bundling in apps without attribution in the UI and would open most of Google Fonts including Roboto, Open Sans and Press Start 2P; without it, the 17 Apache display fonts above plus system fonts are enough for casual games.
- sfxr-family output: only ChipTone states the output licence (CC0); sfxr/jsfxr/Bfxr2 license the tool and are silent on output, which is parameter-driven synthesis by the user with at most thin protection; treat it as the developer's own and record the parameters (jsfxr JSON) in the repository as provenance.
- Codecs: prefer Ogg Vorbis/Opus or platform decoders (Android MediaPlayer/SoundPool, iOS AVAudio, Web Audio) so no codec code is shipped; a common-code decoder would need the permissive libraries above.
- **Notice duties.** MIT/BSD require the copyright and permission notice, Apache-2.0 the licence text and any NOTICE file, in the shipped product: AboutLibraries already covers Gradle dependencies. It does not cover a Kotlin port of Box2D copied into `core`, vendored JS (a portal SDK), fonts or CC0 packs, so these need manual entries in the licences screen (Apache font licence text included).
- **Licensee blind spot → asset manifest test.** Licensee validates Gradle/Maven artifacts only. Add a checked-in manifest (for example `assets.toml`: file path, source URL, author, licence SPDX id, retrieval date, hash) and a JVM test that fails when any file under `composeResources/files`, `font`, `drawable` or the web resources is missing from the manifest or has a licence outside {CC0-1.0, Apache-2.0, MIT, BSD, own work}. The same test can feed the licences screen.
- **Ads.** No allowlisted ad SDK exists; any network is an owner exception like the Play library. The thinnest footprint is Google's own SDKs (already the Android SDK License family, as the in-app update and age-signals libraries) behind the existing `Ads` interface, written directly in `androidMain`/`iosMain` or via basic-ads (MIT wrapper, still beta at 1.3.0-beta01 after months without a stable release, which argues for a small own wrapper). A web build needs a different `Ads` implementation per portal SDK or H5 Games Ads, with the same interface.
